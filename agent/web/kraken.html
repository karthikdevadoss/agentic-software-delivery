The four areas

Access

“connecting people and systems to approved AI models and tools”

Every billed model call goes through one gateway. It checks the call's purpose, reserves budget before the provider is contacted, enforces daily, per-run and per-request caps and a rate limit, records real token usage, and has a kill switch. An opt-in local LiteLLM proxy route is included, and a test fails the build if code calls the SDK directly.

Context

“grounding AI in trusted Kraken knowledge, data and systems”

Ask the Codebase answers from retrieval over the real repository, with sources. Retrieval is local cosine search with content-hash indexing, measured on a labelled set (Recall@3 0.833, MRR 0.868). Document access levels are enforced in code, not in a prompt: chunks the caller may not see are removed before similarity is computed, and an unknown role gets nothing. This runs on fixture documents that stand in for Notion- and Slack-style pages.

Enablement

“reusable building blocks for AI-powered workflows and products”

A LangGraph workflow that checkpoints to Postgres, pauses for a human decision, resumes after a crash and does not repeat its one side effect. The same read-only repository tools serve the Anthropic tool-calling agent and an MCP server, so security logic is written once. Typed Pydantic AI output is used in the Triage lab.

Crash-recovery case study → Workbench verified run → Triage lab →

Governance

“permissions, safety, quality, cost and visibility across the lifecycle”

The model can propose a change but has no code path to approve it; each approval is bound by hash to the exact content. Seven eval suites with written thresholds fail CI when quality drops. A Postgres event ledger with versioned pricing records the cost of every run, and OpenTelemetry spans record gateway, retrieval and approval events. The MCP server requires a bearer token with per-tool scopes.

Evals & Observability

“skill evals, internal benchmarking, agent safety and guardrails, and observability for live AI runs”

A prompt-injection red team: hostile instructions in files the agent reads must never produce an unapproved write (10 attacks, all blocked). Plus labelled suites for retrieval, tool routing, security routing (zero tolerance), recorded agent decisions, permission filtering and self-eval, with run history and a reproducibility hash; per-run cost and spans.

Honest gaps

What I have not done yet

Kubernetes in production: I have local manifests validated in CI (no cluster), and AWS Lambda, SAM and SQS with dead-letter queues from 2025. I would learn your clusters with the squad first. AWS Bedrock, Inspect AI, Ragas: not used yet; my evals are my own harness. Hosted MCP: the MCP server runs and is tested locally, not on the public site. Budgets: the gateway caps are SQLite on the host disk, so they reset on a redeploy; the cost ledger itself is in Postgres.
