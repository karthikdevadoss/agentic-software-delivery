How this platform is built

How I build with AI coding agents

Most of the code on this platform is written by Claude Code, an AI coding agent, working under my direction. I decide what gets built and in what order, I set the rules the agent must work under, and no change is accepted until it has been proven, not just claimed. This page shows those rules, the checks behind them, real mistakes they caught, and what the agent's own work costs.

The rules below are the project's working instructions, kept in the repository and loaded by the agent at the start of every session. Each claim links to the file or pull request where you can check it.

The rules the agent works under

  1. A new test counts only after it has been seen failing. Each new test is run against broken code first, either the old code or a deliberately broken copy. A test that has only ever passed proves nothing.
  2. Skipped is not passed. Every report states pass, fail and skip counts. A risky change whose required checks could not run is reported as unverified, never as done.
  3. Never code against a remembered API. Before using a library call the project has not used before, the agent looks up the real signature in the installed package. Models confidently invent function names; this rule stops that reaching the code.
  4. The builder never signs off its own work. For security-relevant or large changes, a separate reviewer agent checks the result against the original requirement. It can read files and run tests, but it cannot edit anything. The reviewer's definition (no write tools) →
  5. Numbers are computed, never judged. Any rule stated as a number, such as a test threshold or a cost, is decided by a script's real output. The agent may explain the result; it may not make up the verdict.
  6. Agents that can write work in their own copy. A sub-agent allowed to edit files works in an isolated git worktree, so it cannot collide with the main session's changes.
  7. Done means live and checked. Work counts as done only after it is merged, deployed and checked on the real site. HTTP 200 alone is not proof; the change must be visible.

What the agent's work costs

Every session is metered

A hook records each Claude Code session's real token usage, read from the session's own transcript, into the same event ledger as the platform's runtime calls. It is valued at API list price and labelled as subscription usage, never mixed with money actually spent.

The incident that made this matter

In September 2026 a €40 pay-as-you-go API credit ran out in under 7 minutes. A very long session was re-sending its whole history on every turn while running without pauses. Rebuilding that from the session's own transcripts also exposed two defects in the cost telemetry, which were fixed.

What this process does not solve

Same-family review: the reviewer agent is the same kind of model as the builder. It reliably catches skipped checks and unproven claims, but it can share the builder's blind spots on subtle logic. My own review is the independent check. Explaining the code: I direct and review the work rather than typing it, so I hold myself to explaining any part of it from the code itself, not from memory.
