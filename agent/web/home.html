An AI agent that cannot approve its own writes

A change proposed by the model is applied only after a person approves it, and the approval is tied to the exact file and content that was approved. The approve step is not something the model can call.

Limitation: The boundary governs writes made through this platform's own tools, scoped to three path prefixes and two file extensions. It is not a general-purpose policy engine, and it does not govern anything changed outside the platform.

A workflow that survives a crash

Long-running work saves its progress as it goes, so it can pause for a human decision and continue after a restart without repeating anything it already did.

Limitation: The crash drill's process kills were performed locally. In production what has been demonstrated is a restart while the workflow was waiting for approval -- not a kill in the middle of the pipeline, because the pipeline completes in about five seconds and has no pause hook there.

Retrieval that is measured, not assumed

Search quality is scored against a hand-labelled set of questions and expected answers, and the build fails if the scores drop below the recorded thresholds. The same read-only repository tools are also exposed over the Model Context Protocol so other AI clients can use them.

Limitation: Retrieval is a local JSON index with a numpy cosine scan over small corpora, not a managed vector database, and there is no hybrid search or reranking. The MCP server runs locally rather than as a hosted service.

Live

One model boundary, with a kill switch

Every call to a language model goes through one place, which checks what the call is for and can be switched off entirely. A test fails the build if any code tries to bypass it.

Limitation: It is a single-provider boundary. Multi-provider routing and failover are not implemented, and the purpose allowlist is a fixed list rather than a policy language.

Live

Every step and every model call is recorded

Every meaningful step and every model call is written to a durable log, including real token counts. If the log's database is unreachable the events are held locally and sent later rather than lost.

Limitation: Token and cost figures are real where the provider returns them and are labelled unavailable where it does not -- browser and subscription usage has no token data, and an unavailable figure is never shown as a zero or an estimate. This is one person's own traffic, not production load.

A real Java and Spring system underneath

The platform does its engineering work on a genuine Java 21 / Spring Boot application with REST and GraphQL and real PostgreSQL with versioned migrations -- deliberately kept separate from the platform itself, so the AI work is performed on a real system rather than on a demo built to flatter it.

Limitation: It is a realistic enterprise-shaped application, not a system with real users or real load. Several parts are implemented and tested but NOT provisioned in production -- the event-outbox messaging, the cache, and several services in the six-service decomposition -- and none of those is claimed above.

Experimental / paused

An experiment that failed its own test, and was stopped

A multi-model cross-review engine was built to a decision rule fixed in advance, measured against frozen ground truth, and then paused when the evidence failed that rule. The product thesis is unproven. The strongest finding is about measurement rather than the product: every recent headline turned out to be produced by a defect in the evaluation system, in both directions.

Limitation: PAUSED, and the product thesis is UNPROVEN. It demonstrated zero genuine false-to-true corrections and zero genuine baseline false claims, so it must not be read as an accuracy product, as evidence that multiple models improve correctness, or as a partial success. It is evidence of experiment design and engineering judgement, nothing more.

Current scope boundaries

This platform does not claim capabilities it has not implemented. It currently uses one model provider, local cosine retrieval over small corpora rather than a managed vector database, and manually triggered deployment scripts.

Multi-provider routing, managed vector search and hybrid retrieval remain future work.
