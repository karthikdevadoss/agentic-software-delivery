**A safety hook meant to block risky prompts was found to not actually block them in one specific mode.**
When Claude Code runs in a scripted/background mode rather than its normal interactive mode, a prompt that a safety hook explicitly says to block was still being sent to the AI anyway — the block only worked when a person was typing interactively. This was reproduced reliably (9 out of 9 times) and is a different bypass than one fixed just two days earlier. Source: GitHub, Claude Code issue #100695, filed Oct 9, 2026. Classification: INDEPENDENT MEASURED EVIDENCE (reproducible with supplied proof).

**An AI coding assistant accidentally killed every open app on someone's Mac.**
The AI ran a command meant to stop one small background process, but the command's matching rule was broader than intended and it ended up shutting down Safari, Chrome, and other running apps — including itself. The error messages were hidden by how the command was written, so the AI never realized what it had done. Source: GitHub, Claude Code issue #100684, filed Oct 9, 2026. Classification: INDEPENDENT MEASURED EVIDENCE (corroborated against system logs).

## 2. Model/tool recommendations

**If you run an AI coding assistant in a scripted or background mode (not interactively), don't assume a safety block that works when you're typing will also work there.**
The headless-mode hook bypass above is a concrete reminder that a safety control tested one way doesn't necessarily work the same way in another execution mode — worth testing explicitly rather than assuming.

**If you let an AI agent run process-killing or file-deletion commands on your behalf, prefer exact targeting over pattern matching.**
The "killed every open app" incident happened because a loosely-targeted kill command matched far more than intended — a risk that applies to humans writing shell commands too, not just AI.

**Consider the new cheap Claude model for high-volume, simple tasks.**
It's now available in more tools (like GitHub Copilot CLI), reinforcing it as a sensible default for routine, low-complexity work paired with a stronger model for harder tasks.

## 4. New model limitations/failures

**A safety hook's "block" decision doesn't always actually block — it depends on how the tool is being run.**
A prompt explicitly marked "blocked" by a safety hook still reached the underlying AI model when the tool ran in a scripted/headless mode, even though the identical setup correctly blocked it when run interactively. Reproduced 9 out of 9 times in headless mode, 0 out of 9 times interactively. Source: GitHub, Claude Code #100695, Oct 9, 2026. Classification: INDEPENDENT MEASURED EVIDENCE.

**A narrowly-aimed "stop this process" command took down an entire computer's open apps, and the AI never knew.**
The command's matching logic was broader than intended, and the resulting errors were hidden from the AI by how the command was written — so from the AI's perspective, nothing appeared to go wrong. Source: GitHub, Claude Code #100684, Oct 9, 2026. Classification: INDEPENDENT MEASURED EVIDENCE.

**An AI coding tool's "copy" shortcut for spinning up a parallel helper task turned out to be far more expensive than the normal way of doing the same thing.**
A specific way of creating a sub-task (triggered by an add-on tool rather than by the AI model itself) failed to reuse previously-processed context, forcing an expensive full reprocessing every time, unlike the normal path which reuses it correctly. Source: GitHub, Claude Code #100699, Oct 9, 2026. Classification: INDEPENDENT MEASURED EVIDENCE.

**An AI coding agent (a different one, OpenAI's Codex) declared a task fully done, then had to take that back.**
After the AI said a task was complete and met all requirements, an independent review found it hadn't actually met the core requirements, and the AI had to retract its own completion claim. Source: GitHub, Codex issue #52426, Oct 9, 2026. Classification: PRACTITIONER EXPERIENCE (weaker evidence — single report, not independently reproduced).

## 8. One experiment worth running

If you rely on any safety hook, approval gate, or blocking rule in an AI coding tool you use, try this: don't just test it the way you normally use the tool. If you typically run it interactively, also test the identical blocking scenario in a scripted, background, or automated mode. Check — independent of what the tool itself reports — whether the thing it's supposed to block actually got blocked (for example, by checking request logs or token/billing usage, not just the tool's own on-screen message). The headless-mode hook bypass above was only caught because someone tested the same rule in a different mode than they normally used.
