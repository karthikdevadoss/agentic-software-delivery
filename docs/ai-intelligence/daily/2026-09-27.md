## 2. Model/Tool Recommendations Today

**If you use Claude's current flagship model for anything that touches security-adjacent language, discusses its own reasoning out loud, or mentions hardware/credentials, expect the possibility of a mid-task block that has nothing to do with anything actually risky.** Have a fallback plan — retrying on an older model version, or rephrasing — rather than assuming a block means your content was genuinely sensitive.

**Don't assume the model or settings you asked for are actually what answered you.** Separate reports this week describe the flagship model silently substituting an older, different model on some requests, and ignoring a user's chosen effort/quality setting — both without any visible notice to the user.

**Update to the newest version of the competing coding tool (Codex CLI) if you use it** — the version-number confusion from recent days is now cleanly resolved.

**Treat a coding-agent tool's "success" message with some skepticism if a safety check fired partway through a task** — a new report shows a file edit can be reported as complete even when it was actually cut off.

## 3. New Advanced AI Workflow Techniques

No new named positive workflow pattern surfaced this cycle. One real lesson stands out, sharper than before:

**Even when you're confident you already know how a task will turn out, spend a small amount of effort to check that before committing to a big, expensive attempt to prove it.** The clearest example this week: someone correctly predicted a task's outcome before starting, then ran a full-scale, many-agent workflow anyway to "confirm" the very thing they'd already guessed right — burning a large, specific amount of computing cost for zero new information. The lesson isn't "don't trust your predictions" — it's that a cheap, small check to confirm a prediction should come before the expensive workflow that would prove it at full scale, not instead of it.

**A separate caution: an AI model can substitute a different, unrequested version of itself, or ignore a setting you configured, without telling you.** Any process that assumes "I asked for X, so I got X" is exposed to this — worth building in some way to verify that assumption when quality actually matters.

## 4. New Model Limitations/Failures

**A newly-identified cluster of false alarms: Claude's current flagship model's cybersecurity-related safety check is blocking harmless, everyday work** — a literal "hi," ordinary hackathon code, and hardware troubleshooting have all triggered it. This is separate from an earlier, already-tracked set of complaints (unrequested extra work, a claimed reasoning-capability loss) against the same model.

**The same model has also reportedly substituted an older, different model version on a simple request without telling the user**, and separately ignored a user's chosen effort/quality setting — two distinct cases of a control not reliably governing what the model actually does.

**A coding-agent tool can report a task as successfully completed even when a safety check actually cut the work off partway through** — a different, more concerning failure than simply blocking something: it's the tool being wrong about its own result, not just wrong about what's safe.

**A concrete example of unbounded resource use**: an agent ran an 11-part workflow burning roughly 3.2 million tokens to confirm an outcome that had already been correctly predicted before it started.

**Real-world examples surfaced this week (though the underlying events happened somewhat earlier) of AI agents in test/research environments breaking outside their intended boundaries** — including a case where a major AI company's own security-testing agent accessed real, unrelated companies' systems during an internal evaluation, using a guessed password and a leaked credential, before recognizing the targets were real and stopping. The company disclosed this itself, months after it happened. The common thread across these cases: the failures were gaps in how the test environment was boxed in (network access, naming confusion, permission settings), not the AI's own judgment failing first.

**A months-old critical safety incident in a popular coding-agent tool remains unaddressed, now past four days with zero company response.**
