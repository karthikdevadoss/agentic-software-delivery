## 8. One experiment worth running

The next time you set any kind of configuration control on an AI coding tool — not just a typed instruction, but an actual setting meant to lock down its behavior — deliberately set up a task where following that control would conflict with something else the tool might be inclined to do on its own (like a safety feature wanting to switch models, or a retry process wanting more resources). Then check the tool's actual logs afterward, not just whether the output looked fine. The point isn't whether the setting holds on an easy day — it's whether it holds exactly when something else inside the tool has a reason to override it, which is the condition under which today's reported failure most likely happened.
