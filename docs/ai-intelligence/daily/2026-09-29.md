## 3. New Advanced AI Workflow Techniques

**Tagging each AI-generated claim by how it was actually sourced — instead of trusting it all equally — is a concrete way to catch errors before they compound.**
A detailed practitioner bug report proposed having an AI agent explicitly label each factual claim it makes as coming from a primary source (it just read the actual document), a secondary source (it's inferring from related context), memory (a note from earlier in the session), or a guess — and treating anything in the "memory" or "guess" category as unverified until re-checked. This directly targets a real failure pattern: an agent trusting a stale note from earlier in a session ("this file doesn't exist") instead of re-checking, when the file was actually right there. *PRACTITIONER EXPERIENCE*, single detailed report, github.com/anthropics/claude-code/issues (#98055), Sep 29, 2026.

**Running multiple AI agent sessions at once on shared infrastructure can cause them to "cross the streams" — two separate incidents of this surfaced this week, in two different products.**
One report showed a multi-step automated workflow's sub-tasks returning answers to a completely different question — one that happened to be running in a separate, simultaneous session on the same account. A second, unrelated tool had a similar issue where two people sharing the same access credential could accidentally steer each other's AI agent sessions. The common thread: when multiple AI agent runs share the same underlying infrastructure, the boundary between sessions isn't always as solid as it looks — worth adding a sanity check that verifies a response actually answers what you asked, rather than assuming session isolation is guaranteed. *INDEPENDENT MEASURED EVIDENCE* (reproducible, with logs) for the first case; *COMMUNITY SIGNAL* for the second.

## 8. One Experiment Worth Running

**Try asking your AI coding assistant to label its own claims by source — then check how often the "memory" or "guess" labeled ones turn out wrong.**
For your next few multi-step sessions, explicitly ask the model to tag each claim it states as fact: did it just read this from the actual file/doc (primary source), infer it from related context (secondary), recall it from earlier in the session (memory), or guess (inference)?
