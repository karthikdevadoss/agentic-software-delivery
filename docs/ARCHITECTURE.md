# Architecture

## Overview

This repository contains a minimal Spring Boot application used as the
target system for an agentic software delivery experiment. The
application itself is intentionally small so that later stages (RAG,
MCP, autonomous agents) have an easy-to-reason-about baseline.

## Application: customer-app

A single-module Maven project (`app/`) built with Spring Boot 3 and
Java 17.

### Layers

- **Model** (`com.example.customer.model`)
  - `Customer`: JPA entity with `id`, `name`, `email`.
- **Repository** (`com.example.customer.repository`)
  - `CustomerRepository`: Spring Data JPA repository for `Customer`.
- **Service** (`com.example.customer.service`)
  - `CustomerService`: business logic, currently lookup by id and
    creation.
- **Controller** (`com.example.customer.controller`)
  - `CustomerController`: exposes HTTP endpoints.

### Endpoints

| Method | Path             | Description                       |
|--------|------------------|------------------------------------|
| GET    | `/customers/{id}`| Fetch a customer by id, 404 if missing |
| POST   | `/customers`     | Create a new customer              |

### Data

- Storage: H2 in-memory database (`spring.datasource.url=jdbc:h2:mem:customerdb`).
- Schema: generated by Hibernate (`ddl-auto=create-drop`).
- Seed data: one sample customer ("Ada Lovelace") inserted at startup
  via a `CommandLineRunner`.
- H2 console available at `/h2-console` for local inspection.

## What is intentionally missing (Week 1)

- No update-email endpoint yet (this is the sample requirement used to
  exercise the planning agent).
- No authentication/authorization.
- No persistent (non-memory) database.
- No RAG, MCP, or autonomous agents wired into this application.
