# Learning guide: AI Usage, Cost & Value Intelligence

For the owner, to understand the feature well enough to explain and defend
it. Architecture reference: `docs/AI_USAGE_INTELLIGENCE.md`.

## Be accurate about who did what

The implementation (code, tests, page and docs) was **generated by Claude in
Claude Code**. The owner:

* set the requirements (the specification of 28 Nov 2026);
* made the scope decisions: phase 1 plus part of phase 2, a restore-point
  branch first, role checks without logins, manual/CSV/JSON learning input, no
  provider billing APIs;
* directs, reviews and deploys the platform.

Sentences that are true:

* "I specified it and directed an AI coding agent to build it, with tests that
  are required to fail before they count."
* "I decided that subscription usage must never be shown as spend, and that
  public visitors only ever see fictional data."

Sentences to avoid: "I wrote the pricing engine" or "I implemented the
analytics". You can explain the design, but say plainly that AI generated
the implementation.

## Study plan (about 6 hours, in order)

Do each step, then answer its check question **without looking**. If you
can't answer, re-read that part. That is the same verified-learning rule the
feature itself uses.

### 1. Token accounting (45 min)
Read `docs/AI_USAGE_SOURCES.md`, then `agent/usage_intel/events.py`
(`from_anthropic`, `from_openai`).
* **Check:** OpenAI reports `input_tokens = 10,000` with
  `cached_tokens = 4,000`. How many uncached input tokens are there, and why
  does Anthropic's number not need this subtraction?
  *(Answer: 6,000. Anthropic's `input_tokens` already excludes cache reads
  and writes.)*

### 2. Pricing by date (45 min)
Read `agent/usage_intel/pricing.py` and the new entries in
`agent/pricing_config.py`.
* **Check:** why is the price looked up by the event's date and not today's
  date? What label does an event get when it is older than the first verified
  price?
  *(Answer: so a price change doesn't rewrite history. The label is
  `estimated_back_applied`.)*
* **Exercise:** work out by hand the cost of 200k uncached input plus 10k
  output on `claude-sonnet-5-5` ($2 / $10 per 1M). Then compare with
  `test_usage_intel_store.py`.
  *(Answer: $0.40 + $0.10 = $0.50.)*

### 3. Unknown ≠ zero, and no double counting (45 min)
Read `analytics.totals` and `analytics.leaves`.
* **Check:** an agent run has 3 model calls. How many rows carry tokens, and
  why?
  *(Answer: 3. The run itself is a container that groups them and carries no
  tokens.)*
* **Check:** what does the "1004 of 1004 calls priced" note protect against?

### 4. Spend versus value (30 min)
Read `BillingSplitTests` in `test_usage_intel_core.py` and the budget line
in `api.overview`.
* **Check:** why must Claude Code usage not count against a budget?
  *(Answer: it runs on a subscription. The API-price figure is what it
  *would* cost, not money spent per call.)*

### 5. Value and evidence (45 min)
Read `outcomes.py` (`VERIFYING_EVIDENCE`, `value_metrics`).
* **Check:** a task was "completed" according to an AI self-check only. Does
  it count as a verified success? What would make it count?
* **Check:** why does cost per verified success include failed attempts?

### 6. Recommendations and model comparison (45 min)
Read `recommend.py` and `compare.py`.
* **Check:** name the three safeguards that stop a recommendation from being
  over-trusted.
  *(Answer: a minimum evidence volume, confidence plus stated limitations,
  and `requires_evaluation` with no automatic routing change.)*

### 7. Access control and demo isolation (30 min)
Read `access.py`, `api.load`, `test_ai_usage_page.py`.
* **Check:** a visitor calls `/api/ai-usage/overview?dataset=live`. What
  happens, and why is a fallback to demo data the wrong answer?
  *(Answer: 403. Silently returning demo data would let someone mistake it for
  live data.)*

### 8. Tests that were observed failing (30 min)
Read `.claude/rules` / `CLAUDE.md` ("A new test is not trusted until it has
been observed failing"). The commit messages on branch `feat/ai-usage-intel`
record the seeded mutations used.
* **Check:** why is a passing new test not evidence on its own?

## Likely interview questions, with honest outline answers

**"How do you attribute AI cost to teams and projects?"**
Every model call becomes a `UsageEvent` with attribution fields (org, team,
user, project, feature, workflow, agent, task). Cost is estimated from tokens
× the dated list price, and breakdowns group by any of those fields. Coverage
counts show what is missing.

**"How do you know the cost numbers are right?"**
There are hand-computed fixtures in tests, and the per-provider token
meanings are checked against the providers' own docs (sources file with access
dates). The numbers are still estimates, and the page says so. Provider billing
reconciliation isn't connected yet; that would be the next step.

**"How do you measure value, not just cost?"**
Outcomes carry evidence types. Only objective checks and human approval
count as verified. The headline metric is cost per verified success, and
failures raise it.

**"How do you stop a dashboard like this from misleading people?"**
Unknown is shown as unknown, every number has a provenance label, spend is
separated from subscription value, demo data is labelled and isolated, and
recommendations carry limitations and change nothing automatically.

**"What would you do next?"**
1. Enrich the live gateway sink (deterministic IDs, duration, pricing version).
2. Record outcomes automatically from CI results.
3. Reconcile against the providers' billing exports.
4. Add identity (SSO) so the team roles become real.
5. Enforce budgets per scope in the gateway.

**"What part did AI play?"**
All of the implementation. The owner's part was the specification, the
decisions, the review gates (tests observed failing, independent evaluation)
and deployment. Say this directly.
